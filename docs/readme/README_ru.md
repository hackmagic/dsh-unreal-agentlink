# dsh-unreal-agentlink

### Плагин DSH, который отдаёт ваш Unreal Editor под управление агента.

**Чистый мост. Агент планирует; этот плагин только переводит.**

```
DSH agent  ──tool calls──►  dsh-unreal-agentlink  ◄──WebSocket──  Unreal Editor
(plans, decides)            (this plugin: server, translator)   editor dials out
```

[Установка](#установка) · [Требования](#требования) · [12 инструментов](#12-инструментов) · [Конфигурация](#конфигурация) · [Документация](#документация)

<code>npm install &amp;&amp; npm run check</code>

</div>

---

Ваш агент уже умеет читать файлы и выполнять команды. Этот плагин отдаёт ему сам редактор: опрашивать уровень, создавать акторов, редактировать чертежи и материалы, рендерить секвенции, делать снимки экрана, которые он действительно *видит*, и откатывать собственную работу, когда что-то идёт не так.

Он **не планирует задачи**. Планирование — дело нативного агента DSH. Этот плагин — переводчик со слоем безопасности: он превращает намерение агента в команды UnrealAgentLink, а ответы редактора — в форму, на которую агент может действовать.

## Требования

| Пункт | Требование |
|---|---|
| Unreal Engine | 5.0 – 5.8 |
| UnrealAgentLink | сам C++-плагин, положите его в `Plugins/` вашего проекта |
| Node.js | `^22.19.0 \|\| >=24.0.0` |
| Среда выполнения DSH | этот плагин, установленный как bundle |

### UEBox не нужен

Настольное приложение UEBox — **не зависимость**. Это другой клиент того же производителя, который просто тоже использует порт 17860, поэтому одновременный запуск обоих — конфликт портов; на этом вся связь между ними. Доказательства:

- `UnrealAgentLink.uplugin:25-34` объявляет ровно две зависимости, обе входят в состав движка: `IKRig` и `PythonScriptPlugin`. Никакого модуля uebox.
- Каждая запись в `UnrealAgentLink.Build.cs` — модуль движка (UnrealEd / AssetRegistry / MovieScene / Landscape …). Никакого uebox SDK.
- Строка `uebox` встречается во всём исходном коде три раза, и все три — заголовки `// Copyright uebox.ai`.
- Ничто в исходном коде не обращается к uebox.ai. Единственное использование `FHttpModule` читает настройки прокси локальной машины (`UAL_ProxyDiagnostics.cpp:167`).

Как только плагин оказывается в вашем проекте, он работает сам: `StartupModule` безусловно вызывает `Init("ws://127.0.0.1:17860")` (`Core/UnrealAgentLink.cpp:86-97`), отправляет `project.info` в момент подключения и не имеет ни рукопожатия, ни токена, ни аутентификации.

> Чтобы сменить порт: `-UALServer=ws://127.0.0.1:17861` на стороне редактора и настройка `port` на этой стороне.

## Установка

Три части: положите C++-плагин UnrealAgentLink в ваш проект UE, установите этот плагин в DSH и откройте редактор. Это всё — **никакого UEBox, никакого токена, никакого рукопожатия**.

### Шаг 1 — установить UnrealAgentLink в проект UE

1. Скопируйте весь каталог `UnrealAgentLink` в `Plugins/` вашего проекта (или в `Plugins/` движка для глобальной установки).
2. Перегенерируйте файлы проекта, затем откройте проект.
3. Убедитесь, что UnrealAgentLink включён в разделе **Edit → Plugins**. Он автоматически подтягивает две зависимости из состава движка: `IKRig` и `PythonScriptPlugin`.

С этого момента редактор подключается сам: `StartupModule` безусловно вызывает `Init("ws://127.0.0.1:17860")` и повторяет попытки каждые 5 секунд, поэтому **порядок запуска не важен**.

> Порт уже занят (например, UEBox)? Дайте редактору другой и согласуйте его с этой стороной:
> `UnrealEditor.exe MyProject.uproject -UALServer=ws://127.0.0.1:17861`

### Шаг 2 — установить этот плагин в DSH

```bash
git clone <this-repo> dsh-unreal-agentlink
cd dsh-unreal-agentlink
npm install
npm run check      # typecheck (src + tests) + 173 tests + catalog + doc reconciliation, one command
```

Прежде чем идти дальше, `npm run check` должен быть полностью зелёным: он проверяет, что исходники и тесты типизируются, поведенческие тесты проходят, и каталог из 170 команд сходится с реестром C++ запись за записью.

Затем зарегистрируйте его как bundle DSH. `package.json` объявляет `dsh.bundle.patch: ./cordis.patch.yml`, а этот файл делает ровно одну вещь:

```yaml
- insert:
    - id: unreal-agentlink
      name: dsh-unreal-agentlink
```

> **Наслоение конфигурации**: более поздний слой **заменяет** `config` этой строки целиком, а не глубоко сливает его. Чтобы переопределить что угодно, перепишите все ключи, которые хотите сохранить.

DSH не поставляется командой, которая устанавливает локальный внедеревящий плагин, а `dsh plugin --profile desktop` отклоняется сразу, потому что профилем `desktop` управляет исключительно приложение Electron (`bin.js:38`). Поэтому этот репозиторий поставляет собственный установщик, который делает работу, а затем передаёт её настоящему:

```bash
npm run status:dsh -- --profile web     # что зарегистрировано прямо сейчас (тот же скрипт, проброс через npm)
node scripts/install-dsh-plugin.mjs --profile web             # зеркалирование, правка манифеста, установка, проверка
```

Он отказывается работать с профилем `desktop`, отказывается трогать манифест, который всё ещё удерживает запущенный DSH, и доказывает, что слой скомпонован, прежде чем сообщить об успехе (`dsh --profile web --dump-config` должен содержать `# == dsh-unreal-agentlink`). Если установку останавливает защита peer-зависимостей, он печатает точную команду для принятия риска — **это решение за вами, а не за скриптом**.

Ещё два пути, оба расписаны: [ручная установка](#ручная-установка-без-скрипта) ниже и [INSTALL-ai.md](../ru/INSTALL-ai.md) — версия, которую ИИ-агент может читать и выполнять шаг за шагом.

### Шаг 3 — открыть проект и проверить

Откройте проект UE, затем попросите агента вызвать `ual_status` и проверьте три поля:

```
listening: true
url: ws://127.0.0.1:17860
editors: [ { sessionId: "ue-xxxxxxxx", project: "MyProject", ... } ]
```

- `listening: false` → плагин не стартовал, либо порт занят. Ищите `EADDRINUSE` в журнале DSH.
- `listening: true`, но `editors: []` → мост ждёт. Убедитесь, что проект UE открыт и UnrealAgentLink включён.

В течение **первого мгновения** после подключения редактора его запись содержит только `sessionId` / `connectedAt` / `lastSeenAt` / `heartbeats` / `stale`; такие поля, как `project`, появляются только когда редактор отправит `project.info`. Это нормальное состояние, а не ошибка.

Затем попробуйте чистое чтение без побочных эффектов:

```
ual_call { method: "level.get_current" }
```

**Полный сквозной путь — рабочие процессы, чтение сбоев, устранение неполадок — в [руководстве](../ru/01-tutorial.md).**

### Ручная установка без скрипта

Скрипт выше — это удобство; лежащий в основе механизм — четыре строки манифеста плюс одна продуктовая команда. Где `<profile>` — это `web` (или любой не-desktop профиль), а `$DSH_HOME` по умолчанию равен `~/.dsh`:

```bash
# 1. собрать один раз, затем скопировать только то, что поставляет npm pack
npm run build
cp -r lib cordis.patch.yml package.json LICENSE README.md \
      "$DSH_HOME/profiles/<profile>/.vendor/"

# 2. зарегистрировать зависимость и слой bundle (нужны оба)
"$DSH_HOME/profiles/<profile>/package.json"    # добавьте две записи, показанные ниже

# 3. позволить настоящему установщику отработать
dsh plugin --profile <profile> install

# 4. доказать, что слой скомпонован
dsh --profile <profile> --dump-config | grep -A2 '# == dsh-unreal-agentlink'
```

Две записи, в `<profile>/package.json`:

```json
"dependencies": { "dsh-unreal-agentlink": "file:C:/Users/you/.dsh/profiles/web/.vendor" },
"dsh": { "profile": { "bundles": ["@deepseek-ai/dsh-base", "dsh-unreal-agentlink"] } }
```

Обе обязательны, и они ломаются по-разному: указанный пакет, который не объявляет `dsh.bundle`, падает **громко** при загрузке, тогда как установленный пакет, который не указан в списке, не даёт **никакого слоя вообще**, и ничего не появляется в `--dump-config`.

**Почему `file:` указывает на копию, а не на ваше рабочее пространство**: pnpm копирует то, что находит в момент установки, поэтому полусохранённый файл исходника — или удалённый `lib/` после неудачной сборки — становится тем плагином, который загружает DSH. Сначала зеркалируйте, потом устанавливайте.

**У профиля `desktop` нет пути через CLI.** `bin.js:38` отклоняет его, потому что приложением Electron управляет исключительно оно, и это приложение удерживает блокировку `wx` на `desktop/package.json`, пока работает (`dsh-atomic-write`, а претендент никогда не удаляет чужую блокировку). Ваши варианты — собственный менеджер плагинов GUI, либо закрыть приложение и выполнить четыре шага выше вручную. Установка сначала в `web` с последующим копированием результата — наименее инвазивный путь.

## Сначала четыре факта

Это не выборы архитектуры. Это существующие ограничения UnrealAgentLink, и они определяют, как пишется каждая операция.

1. **Направление обратное.** Этот плагин не звонит редактору — **редактор сам подключается**. Порядок запуска не важен: откройте редактор первым, и он будет повторять попытки каждые 5 секунд, пока плагин не появится.
2. **Аутентификации нет.** Ни токена, ни заголовка, ни подпротокола. **Порт и есть учётные данные**, поэтому по умолчанию он слушает только loopback. Не меняйте его на `0.0.0.0`.
3. **Команды выполняются последовательно в игровом потоке.** И пока выполняется блокирующая команда, **редактор не отвечает ни на что** — даже на запрос прогресса вроде `sequence.render_status`.
4. **Отмены нет.** `query_task` и `cancel_task` не существуют. Убийство задания `ual_task` останавливает только ожидание этого плагина; движок продолжает работу, и результат всё равно придёт.

## 12 инструментов

Выставить 170 команд как 170 инструментов — значит потратить большую долю промпта каждого запроса на возможности, которых данная задача никогда не коснётся. Поэтому обнаружение возможностей занимает два шага, а не ноль:

| Инструмент | Назначение |
|---|---|
| `ual_status` | Подключения редактора / предохранитель (circuit breaker) / ограничение частоты / сессии / зависшие команды. **Читайте это первым, когда что-то не так** |
| `ual_tools` | Список всех 170 команд (22 семейства), с фильтром по семейству или ключевому слову |
| `ual_schema` | **Точные имена ключей** для одной команды — проверяйте перед вызовом; UE молча игнорирует неизвестные ключи |
| `ual_call` | Выполнить одну команду, вернуть результат редактора дословно |
| `ual_batch` | Несколько команд одним обменом (ограничено `maxBatchCalls`; один опасный элемент проводит через утверждение весь пакет) |
| `ual_screenshot` | Снять и вернуть **настоящее изображение**, которое видит агент |
| `ual_logs` | Читать локальное кольцо журнала (пересылка с стороны UE по умолчанию выключена — см. руководство) |
| `ual_undo` / `ual_undo_history` | Откат в рамках сессии / просмотр буфера отмен |
| `ual_locks` | Занять блокировки ассетов; редактор рисует значок «ИИ редактирует» |
| `ual_editor_bind` | Привязать сессию к одному редактору, когда подключено несколько |
| `ual_task` | Превратить долгую блокирующую команду в настоящее фоновое задание, чтобы разговор продолжался |

### Уровни риска

read 65 / write 89 / **destructive 2 / dangerous 14** (последние 16 проходят через утверждение).

`tools/pre-execute` возвращает `{kind:'ask'}` для destructive- и dangerous-методов (включая любой опасный элемент внутри `ual_batch`), оставляя решение политике сессии. **Незарегистрированный метод отклоняется сразу** и никогда не доходит до редактора.

Обратите внимание: при политике `never` запрос `ask` автоотклоняется — что и есть правильное прочтение «неконтролируемые сессии не должны трогать редактор».

npm run build       # tsc → lib/

### Структура исходного кода

```
src/
  index.ts                  Cordis lifecycle, approval gate, dispose-time rollback
  config.ts                 Schemastery schema (the single source of default values)
  service.ts                call() gate chain: catalog → requires → read cache → breaker → rate limit → send → ledger → translate
  protocol/{bridge,serialization,types}.ts   WS server / outbound validation / wire types
  catalog/{method-data,method-overrides,methods}.ts   170-command catalog (data extracted from C++)
  errors/translate.ts       Error classification (by class name / status code, never by message text)
  resilience/breaker.ts     Rate limiter + circuit breaker
  sessions/state.ts         Session ledger / LIFO test / lock merging / cache / log filtering
  tools/                    The 12 tools
scripts/                    Извлечение каталога и сверка, генерация и нормализация документации,
                              набор языков и установщик профилей DSH
docs/                       Руководство / протокол / архитектура / справочник команд / руководство по установке,
                              на 9 языках
tests/                      173 tests
```

### Сгенерированные файлы: не править вручную

`src/catalog/method-data.ts` и `docs/command-reference.md` оба **генерируются**:

```bash
node scripts/extract-methods.mjs .ua-ref/plugin/UnrealAgentLink/Source   # rebuild the catalog from C++
npm run build && node scripts/gen-docs.mjs                             # rebuild the command reference
```

Поддерживаемая вручную таблица, которую никто не импортирует, — повторяющийся класс дефектов в этом проекте (так были пойманы `REQUIRED_KEYS`, `EXTRA_PARAM_KEYS` и `UAL_CODES`). Контрмера — заставить каждую проверку **спрашивать источник**, а не таблицу — см. [архитектура §9](../ru/03-architecture.md#9-сгенерированные-файлы-и-таблицы-которые-никто-не-импортирует).

### Тесты и проверки

```bash
npm run check                       # typecheck (src + tests) + 173 passed + catalog + doc reconciliation
npm test                            # 173 passed
node scripts/check-catalog.mjs      # 170/170 zero drift; every requires key appears in C++; code set matches C++
node scripts/gen-docs.mjs --check   # is the command reference up to date
```

Семь тестовых файлов разделены по **роду дефектов, которые они способны найти**, и каждый — по своей причине — см. [архитектура §11](../ru/03-architecture.md#11-стратегия-верификации).

`requires` не пишется руками: он выводится из собственных сообщений `SendError(..., 400, "Missing field: X")` в обработчиках (28 мест), потому что неверный обязательный ключ заставляет мост отклонить *корректный* вызов ещё до того, как его увидит движок. Результат попадает в `method-data.ts` как `REQUIRED_KEYS`, а `requiresOf()` в `methods.ts` встраивает его в работу во время выполнения (раннее отклонение в `service.call()`, строка `REQUIRED:` в `ual_schema` и подсказки в ошибках — всё через эту одну функцию).

Он намеренно **сужает, но никогда не расширяет**: сообщение, содержащее `or` (`"Missing field: name or path"`), пропускается целиком, а ключи, добытые из вызванной функции в том же файле, отбрасываются как локальные для ветки — см. `REQUIRED_DROPPED` в `scripts/extract-methods.mjs`, где каждая запись ссылается на номер своей строки C++. Так что «ключей не добыто» — безопасное поведение по умолчанию, а не пропущенная проверка.

## Основы протокола

```
UE → plugin:  { ver:"1.0", type:"req",  method, id, params }     // id is generated by the server
plugin → UE:  { ver:"1.0", type:"res",  id, code, result }        // the key is omitted when empty
UE → plugin:  { ver,       type:"evt", method, payload }
```

- Сбой выражается **только через `code`**. Поля `error` на уровне конверта нет.
- Читаемый человеком текст лежит в `result.message` (на китайском или английском в зависимости от локали редактора — **не парсите его**); машинно-читаемые подробности — в `result.details`.
- **Многие обработчики возвращают `200` при `result.ok === false`** (`editor.undo`, `blueprint.compile`, `pie.observe`), поэтому плагин судит об успехе через `judge()`, а не по одному коду. Есть 55 мест `SetStringField(TEXT("error"), ...)` в 14 файлах C++ — это норма, а не аномалия.
- `content.import_folder` / `content.import_assets` — **исходящие push'ы в режиме «отправил и забыл»**: ни `id`, ни ожидания ответа. Плагин превращает их в записи журнала и уведомления агента и **не фабрикует `res`** — ответ `ok:false` лишь показал бы пользователю ложный диалог «импорт не удался», что хуже молчания.

Полные подробности (все 13 кодов состояния, правила сериализации, семантика таймаутов) — в [справочнике по протоколу](../ru/02-protocol.md).
