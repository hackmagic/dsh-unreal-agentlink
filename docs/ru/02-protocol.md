# Справочник по протоколу

Проводной протокол UnrealAgentLink. Этот плагин — **сервер**; Unreal Editor — **клиент**.

Каждый вывод здесь исходит из C++ в `.ua-ref/plugin/UnrealAgentLink/Source/UnrealAgentLink/`, со ссылками на файл и строку в несущих точках.

---

## 1. Подключение

| Пункт | Значение | Свидетельство |
|---|---|---|
| Направление | UE подключается сам | `Network/UAL_NetworkManager.cpp:77` `CreateWebSocket(TargetUrl)` |
| Адрес по умолчанию | `ws://127.0.0.1:17860` | `Core/UnrealAgentLink.cpp:88` |
| Как изменить | командная строка `-UALServer=ws://host:port` | `Core/UnrealAgentLink.cpp:90` |
| Аутентификация | **нет** — ни токена, ни заголовка, ни подпротокола | `CreateWebSocket` принимает только URL |
| Переподключение | фиксированный 5-секундный цикл, без backoff | `Network/UAL_NetworkManager.cpp:116` |
| Защита от зависания подключения | есть (`ConnectTimeoutSeconds`) | `Network/UAL_NetworkManager.cpp:145-155` |

Этот плагин слушает 17860 с `maxPayload` в 64 МБ.

### Проверка Origin

Принимаются только loopback-ориджины (`127.*`, `::1`, `::ffff:127.*`). Расширяется только если настроенный `host` **намеренно** установлен в что-то иное, кроме `127.0.0.1` / `localhost`. Причина — в «аутентификации нет»: порт и есть учётные данные.

### Рукопожатие

**Рукопожатия нет.** Редактор отправляет `project.info` сразу при подключении, и этот плагин использует это, чтобы пометить его идентифицированным (`editor-identified`). Пока оно не придёт, соединение «подключено, но не идентифицировано» — такая запись в `ual_status` содержит только `sessionId` / `connectedAt` / `lastSeenAt` / `heartbeats` / `stale`, без `project` и прочего.

## 2. Форматы сообщений

```
UE → plugin:  { ver:"1.0", type:"req",  method, id, params }
plugin → UE:  { ver:"1.0", type:"res",  id, code, result }
UE → plugin:  { ver:"1.0", type:"evt",  method, payload }
```

### `req` (этот плагин → редактор)

| Поле | Примечания |
|---|---|
| `ver` | всегда `"1.0"` |
| `type` | `"req"` |
| `method` | имя команды, например `actor.get_info` |
| `id` | генерируется **сервером**, имеет вид `dsh-<uuid>` |
| `params` | необязательны. **Пустые — ключ опускается целиком**, а не отправляется как `null` |

`id` не должен быть пустым: первая строка `SendResponse` — `if (RequestId.IsEmpty()) { return; }` (`Utils/UAL_CommandUtils.cpp:2503-2506`) — **запрос без `id` никогда не получит ответа**.

На стороне редактора разбор (`Commands/UAL_CommandHandler.cpp:87-94`) читает сначала `params`, а при отсутствии откатывается к устаревшему полю `payload`. Этот плагин отправляет только `params`.

### `res` (редактор → этот плагин)

| Поле | Примечания |
|---|---|
| `ver` | `"1.0"` |
| `type` | `"res"` |
| `id` | повторяет `id` запроса, используется для сопоставления |
| `code` | **число**, а не строка |
| `result` | необязателен. **Пустой — ключ опускается целиком** |

Логика опускания — в `Utils/UAL_CommandUtils.cpp:2513-2516`: `result` пишется только когда `Data.IsValid()`.

На стороне редактора разбор тела ответа (`Commands/UAL_CommandHandler.cpp:98-104`) пробует по порядку `result` → `data` → `payload`. Этот плагин отправляет `result`.

### `evt` (редактор → этот плагин, односторонний push)

| Поле | Примечания |
|---|---|
| `ver` | присутствует, когда событие отправлено через `SendEvent`; **события импорта из расширения браузера контента его не содержат** |
| `type` | `"evt"` |
| `method` | имя события |
| `payload` | необязателен |
| `id` | **не существует** — на события нельзя ответить |

## 3. Как выражается сбой

**Только через `code`.** Поля `error` на уровне конверта в сообщении **нет**.

| Код | Значение | вид этого плагина |
|---|---|---|
| `200` | успех | — |
| `207` | частичный успех | `partial: true` |
| `400` | параметр отсутствует или неверно типизирован | `bad-params` |
| `404` | нет такого метода или ассета | `not-found` |
| `409` | конфликт (например, эксклюзивный профайлер уже запущен) | `conflict` |
| `410` | удалено | `not-found` |
| `412` | предусловие не выполнено | `precondition` |
| `413` | превышен предел (например, пакетное создание сверх лимита cvar) | `precondition` |
| `422` | ввод корректен, но ничего не записано | `precondition` |
| `500` | внутренняя ошибка редактора | `engine-error` |
| `501` | не поддерживается в этой версии | `unsupported` |
| `503` | реестр ассетов ещё сканирует | `registry-busy` |
| `504` | таймаут на стороне редактора | `timeout` |

`0` **никогда не используется**.

Эти 13 кодов определены в `protocol/types.ts` как `UAL_CODES`, и проверка 4 из `scripts/check-catalog.mjs` запрашивает для них исходный код C++ напрямую — включая 503, который испускают общие шлюзы вроде `FUAL_RegistryReady::Ensure`, и формы выражений вроде `Code = bOk ? 200 : 207`. Отсутствие или лишний код валят проверку.

### Где живёт текст ошибки

```
result.message   ← for humans, Chinese or English by editor culture, never parse it
result.details   ← for machines (suggestions / expected_type / registry progress)
```

`SendError` строит `{message: ...}`, а перегрузка с 4 аргументами прикрепляет ещё и `details` (`Utils/UAL_CommandUtils.cpp:2525-2539`).

### 200 всё ещё может быть сбоем

**Это самая лёгкая ловушка.** Многие обработчики возвращают `200` при `result.ok === false`:

- `editor.undo` — когда отменять нечего
- `blueprint.compile` — когда в компиляции есть ошибки
- `pie.observe` — когда наблюдение не удалось

Поэтому этот плагин судит об успехе через `judge(result, code)`, а не по одному коду:

| Ситуация | Приговор |
|---|---|
| `code === 200`, `result.ok !== false`, `result.error` пуст | успех |
| `code === 207` | успех, но `partial: true` |
| `result.ok === false` | **сбой** |
| `result.error` — непустая строка | **сбой** |
| `result` не объект (или отсутствует) | судить по коду; не гадать |

Это правило **необходимо**: есть 55 мест `SetStringField(TEXT("error"), ...)` в 14 файлах C++. Иными словами, «200 с непустой ошибкой» — норма, а не аномалия.

## 4. События

| Событие | Когда | Нагрузка |
|---|---|---|
| `project.info` | сразу при подключении, заменяет собой рукопожатие | имя проекта, путь, версия движка, версия плагина, режим запуска, текущий уровень, доступность Python и многое другое |
| `project.closed` | редактор закрывает проект | — |
| `system.heartbeat` | каждые **10 секунд** | `{}` (**всегда присутствует**, не опускается) |
| `log.entry` | вывод журнала UE (требует cvar `ual.ForwardLogs 1`) | `text` / `category` / `level` |
| `content.import_folder` | пользователь выбирает «импорт в библиотеку ассетов UnrealBox» в контекстном меню браузера контента | `paths` / `real_paths` / `asset_metadata` |
| `content.import_assets` | то же самое, но инициировано из видового порта уровня | `asset_paths` / `asset_real_paths` / `asset_metadata` |

### Сердцебиения и признание редактора мёртвым

Сердцебиения — **независимый 10-секундный тикер** (`Network/UAL_NetworkManager.cpp:173`), не связанный с 5-секундным переподключением. Этот плагин помечает редактор `stale` после **45 секунд** без сердцебиения — совпадая с фронтендом (`Network/UAL_NetworkManager.cpp:172`).

### Два события импорта — в режиме «отправил и забыл»

Они не несут **никакого `id`**, и редактор **не ждёт ответа**. Редакторный `Handle_Response` (`Commands/UAL_CommandHandler.cpp:185-297`) показывает Slate-уведомление только когда получает `type:"res"`, читая `ok` / `count` / `importedPath` / `error`.

Этот плагин — чистый мост без возможности импортировать ассеты, поэтому он превращает события в **записи журнала и уведомления агента** и **не фабрикует `res`** — ответ `ok:false` лишь показал бы пользователю ложный диалог «импорт не удался», что хуже молчания.

## 5. Правила сериализации

Исходящие параметры проходят через `toSerializable()` в `protocol/serialization.ts` перед уходом в провод. Он строже, чем `JSON.stringify`, потому что **UE трактует поле, которое не может прочитать, как «не отправленное»** — молча ничего не сделать тяжелее диагностировать, чем выдать ошибку.

| Ввод | Обработка |
|---|---|
| `null` / логическое / строка | как есть |
| конечное число | как есть |
| **неконечное число** (`NaN` / `Infinity`) | **выбрасывает** — UE прочло бы его как «поле отсутствует» |
| `undefined` (верхний уровень или внутри массива) | **выбрасывает** |
| `undefined` (как значение свойства объекта) | **ключ отбрасывается** |
| функция / символ / bigint | **выбрасывает** |
| круговая ссылка | **выбрасывает** |
| `Uint8Array` | преобразуется в строку base64 |
| `Date` | преобразуется в строку ISO |
| `Map` (ключи должны быть строками) | преобразуется в простой объект |
| `Set` | преобразуется в массив |
| прочие непростые объекты (экземпляры классов и т.п.) | **выбрасывает** |

Проходят только простые объекты, массивы и JSON-скаляры.

## 6. Тайминги и конкурентность

**Команды к одному редактору последовательны.** Этот плагин держит по одной очереди отправки на редактор, нанизывая каждую команду на `then` предыдущей. Это не для удовлетворения протокола — это потому, что редактор и так выполняет синхронно до завершения в игровом потоке.

**Очереди независимы между редакторами.** Когда подключается несколько редакторов, каждый получает свою очередь.

### Таймауты

По умолчанию 180 секунд, и блокирующие команды поднимают собственные минимумы (столбец таймаута в `ual_schema` помечает их «blocking»).

**Таймаут не означает, что команда не выполнилась.** Он означает только, что этот плагин перестал ждать. Когда это происходит:

1. Редактор помечается как имеющий зависшую команду (`orphaned` в `ual_status`).
2. Последующие **короткие команды к этому же редактору отклоняются сразу** (`queue-stalled`), а не ставятся в очередь за работой, которая, возможно, никогда не вернётся.
3. Вызов `long: true` всё ещё может быть отправлен — именно так выражается «я согласен ждать».

**То же относится и к прерванным вызовам**: убийство задания `ual_task` проходит через abort, а abort останавливает только ожидание этого плагина, движок продолжает работать. Так что abort тоже записывает зависшую команду.

### Отключение

Когда редактор отключается, каждый незавершённый запрос к нему падает с `editor-lost`, и ошибка несёт все имена методов.

## 7. Чего этот плагин не отправляет

Чтобы явно обозначить границу:

- **Никакого токена** — механизма аутентификации не существует.
- **Никакого `GET /api/ual/action`** — старая документация описывала это как HTTP-сервис; это неверно.
- **Никакого опроса задач** — `query_task` / `cancel_task` не существуют.
- **Никакого сфабрикованного `res`** — см. раздел о событиях импорта.
- **Никакого активного переподключения к редактору** — направление обратное; редактор повторяет попытки каждые 5 секунд сам.
