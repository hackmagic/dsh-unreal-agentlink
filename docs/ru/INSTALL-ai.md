# Установка (версия, читаемая ИИ)

Этот файл написан для ИИ-ассистента, который читает файлы и выполняет шаги по порядку.
Не пропускай шаги: у каждого шага есть проверяемый результат. Для установки вручную см.
[README](../readme/README_ru.md) или [руководство](01-tutorial.md).

> ИИ достаточно запустить только `scripts/install-dsh-plugin.mjs`. Этот скрипт делает
> всё: зеркалирование → правка манифеста профиля → вызов настоящего установщика →
> проверка скомпонованного результата. Каждый шаг ниже — это **контрольная точка**:
> если шаг не совпадает с ожиданием, остановись и сообщи об этом. Не продолжай.

---

## 0. Сначала проверь (только чтение, ничего не устанавливает)

```bash
node scripts/install-dsh-plugin.mjs --profile web --status
```

В выводе `installed copy:` и `bundle layer:` должны читаться как `present` / `listed`. Только
если они читаются как `(absent)` / `(not listed)`, нужно выполнять установку.

Затем проверь сторону UnrealAgentLink:

- В проекте существует `Plugins/UnrealAgentLink/`, и он включён в разделе
  `Edit → Plugins` (редактору требуется перезапуск).
- Порт 17860 свободен (`uebox` desktop занимает тот же порт; этому плагину он не
  нужен).

---

## 1. Установка (одна команда)

```bash
npm run build && node scripts/install-dsh-plugin.mjs --profile web --yes
```

Скрипт выполняет пять действий, каждое из которых оставляет свидетельство:

| Шаг | Артефакт | Что означает при неудаче |
| --- | --- | --- |
| сборка | `lib/`, 64 файла | сначала запусти `npm run check`; не устанавливай сломанную сборку |
| зеркалирование | `<profile>/.vendor/`, содержащий только записи `files` | проблема с диском или правами |
| правка манифеста | `<profile>/package.json` получает одну строку dependency + одну строку bundle | см. §4 |
| установщик | pnpm печатает `Done in Xs` | см. §2 |
| проверка | `install: ... is now a bundle layer of profile "web"` | см. §3 |

**Только последняя строка означает, что установка прошла успешно.** Если первые четыре шага
прошли, а пятый — нет, слой не скомпонован, и dsh не загрузит плагин.

---

## 2. Если установщик отказывает (защита версий)

У dsh есть продуктовый механизм защиты: установка отклоняется, когда `peerDependencies`
плагина несовместимы с версией dsh в runtime. Этот проект
фиксирует `@deepseek-ai/*` на `0.1.6-alpha.2`, тогда как поставляемый dsh — `0.2.0-rc.2`,
поэтому установка останавливается здесь.

**Это продуктовое решение; скрипт намеренно не принимает его за тебя.**
Он печатает точную команду:

```bash
dsh plugin --profile web allow-version dsh-unreal-agentlink@0.1.0 --dsh-version 0.2.0-rc.2 --accept-risk
```

Её выполнение требует подтверждения человеком. Затем повтори установку из §1.

> В выводе `--status` строка `version guard:` показывает, активно ли уже
> исключение.

## 3. Если шаг проверки не проходит (слой не скомпонован)

```bash
dsh --profile web --dump-config | grep unreal-agentlink
```

Это должно напечатать:

```
# == dsh-unreal-agentlink
- id: unreal-agentlink
  name: dsh-unreal-agentlink
```

Три известные причины, если это не так:

1. `dsh.profile.bundles` не содержит этот плагин — скрипт должен был добавить
   его; проверь `<profile>/package.json`.
2. Пакет есть в `node_modules`, но не объявляет `dsh.bundle` — при загрузке это падает
   **громко** (`declares no dsh.bundle in its package.json`); проверь
   зеркалированный `package.json`.
3. Сама команда `--dump-config` выдаёт ошибку — сообщи полный вывод дословно, не
   догадывайся.

## 4. Если правка манифеста отклонена блокировкой

```
install: <path>/package.json.lock is held by pid 18344 (DeepSeek Harness)
```

dsh защищает манифест профиля соседним файлом `.lock`, созданным с флагом `wx`, и
**претендент никогда не удаляет чужую блокировку**. Держателем блокировки является
само работающее приложение dsh.

- Для профиля `web`: закрой работающее десктопное приложение DeepSeek Harness или выбери
  профиль, который не занят.
- Для профиля `desktop`: команда *загрузки* CLI **запрещена** (`bin.js:112`
  `rejectElectronProfile`), но `dsh plugin --profile desktop …` намеренно освобождён
  от запрета (`bin.js:119`) — это путь, которым пользуется поставляемый с Desktop CLI,
  вызываемый самим приложением. Продукт просит сначала полностью закрыть приложение,
  потому что работающее приложение переписывает манифест из собственного списка
  плагинов. Закрой его, выполни установку и запусти Desktop после этого, чтобы
  смонтировать слой.
- Скрипт отказывается и называет держателя блокировки; он не борется с блокировкой.

## 5. Убедись, что плагин действительно работает (быть установленным недостаточно)

```bash
# a) Сторона редактора: открой проект. В журнале UE должно появиться подключение.
#    (UnrealAgentLink повторяет попытки каждые 5 секунд; ручное подключение не нужно.)

# b) Сторона DSH: попроси агента в сессии «проверить редактор через ual_status».
```

Три поля `ual_status` и есть критерии приёмки:

| Поле | Ожидается |
| --- | --- |
| `listening` | `true` |
| `editors` | хотя бы один, с именем `project` |
| `orphanedMethods` | `[]` |

`listening: false` = никто не слушает (плагин не загружен или порт занят).
`editors: []` = UE не подключился (проект закрыт, плагин выключен или несовпадение порта).
Непустой `orphanedMethods` = запрос истекла по таймауту, но ещё может выполняться;
проверь `ual_logs` перед повтором.

Затем подтверди весь путь одной минимальной командой:

```bash
# в сессии: ual_call { "method": "level.get_current" }
```

---

## 6. Удаление

```bash
node scripts/install-dsh-plugin.mjs --profile web --remove --yes
```

Скрипт удаляет и запись dependency, и запись bundle, затем запускает настоящий
установщик, чтобы pnpm синхронизировал `node_modules`. Каталог зеркала
`<profile>/.vendor` сохраняется и перестраивается при следующей установке; удали его
вручную, если хочешь избавиться от него.

## Жёсткие правила для ИИ

1. **Не** правь `peerDependencies` этого проекта, чтобы заставить установку пройти —
   это скрыло бы настоящую несовместимость версий.
2. **Не** правь `<profile>/package.json` вручную; это делает скрипт, и он
   проверяет блокировку.
3. **Не** считай `--accept-risk` автоматически выполнимым; он требует подтверждения
   человеком.
4. Если вывод любого шага отличается от описанного, **остановись и сообщи
   вывод дословно**; не «попробуй исправление и перезапусти».
5. Каждый шаг здесь можно перепроверить командами только для чтения (`--status`,
   `--dump-config`, `ual_status`).
