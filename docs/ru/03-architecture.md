# Архитектура

Этот плагин — **чистый мост**: он не планирует задачи и не решает, что делать. Он переводит намерение агента DSH в команды UnrealAgentLink, а ответы редактора — в форму, которую агент может использовать. Планирование принадлежит агенту DSH, а не здесь.

Этот раздел объясняет, почему код выглядит именно так.

---

## 1. Карта модулей

```
src/
  index.ts          Cordis lifecycle, approval gate, dispose-time rollback
  config.ts         Schemastery schema (the single source of default values)
  service.ts        call() gate chain — the one entry point for every command
  protocol/
    bridge.ts       WebSocket server: connections, queues, timeouts, orphans, log ring
    serialization.ts  outbound parameter validation (stricter than JSON.stringify)
    types.ts        wire types and UAL_CODES
  catalog/
    method-data.ts      five tables extracted from C++ (generated, do not hand-edit)
    method-overrides.ts  manual patches where the extractor cannot reach
    methods.ts          170 commands with risk tier and summary + query functions
  errors/translate.ts   error classification (by class name / status code, not by text)
  resilience/breaker.ts rate limiter + circuit breaker
  sessions/state.ts     session ledger, LIFO test, lock merging, cache, log filtering
  tools/                те 12 инструментов
scripts/
  extract-methods.mjs   извлекает каталог из C++ (генерирует method-data.ts)
  check-catalog.mjs     сверяет каталог с реестром C++ в обе стороны
  gen-docs.mjs          отрисовывает docs/<lang>/command-reference.md для всех 9 языков
  languages.mjs         набор языков — общий для генератора и тестов документации
  normalize-doc-headers.mjs  перезаписывает языковые панели и строки навигации по набору языков
  normalize-doc-links.mjs    перезаписывает ссылки тела, чтобы они разрешались из своего файла
  install-dsh-plugin.mjs     регистрирует этот плагин в профиле dsh (зеркало, манифест, установка, проверка)
docs/                   учебник / протокол / архитектура / справочник команд / руководство по установке,
                         ×9 языков
tests/                  173 теста в 9 файлах
```

### Направление зависимостей

```
index.ts ──► service.ts ──► protocol/bridge.ts
    │            │
    │            ├──► catalog/methods.ts ──► catalog/method-data.ts
    │            ├──► resilience/breaker.ts
    │            ├──► sessions/state.ts
    │            └──► errors/translate.ts
    └──► tools/* ──► service.ts
```

Обратных зависимостей нет. `tools/` зависит только от `service`, а `service` не зависит ни от одного инструмента.

## 2. Цепочка шлюзов: `service.call()`

**Каждая** команда проходит через эту единственную точку входа (`src/service.ts:190-332`) в фиксированном порядке:

```
1. catalog gate    the method is not in the catalog → refuse, never forward
2. requires gate   a required key is missing → refuse, never forward
3. read cache      read-only + cacheable + not long → return, never touch the socket
4. breaker         acquire() throws when open / admit() lets exactly one half-open probe
5. rate limit      throws when the queue is full
6. send            bridge.send() → the editor
7. judge()         200/207 plus result.ok/error decides success
8. ledger          recorded only when the call both mutates and succeeds
9. translate       on failure, classify by class name / status code
   finally         breaker.release()
```

Ценность первых двух шагов в том, что они **отказывают ещё до того, как движок увидит вызов**. UE молча игнорирует неизвестные ключи, поэтому опечатка в имени ключа делает вызов «успешно» ничего не сделав — что гораздо труднее отлаживать, чем ошибка.

`call()` **никогда не бросает исключений**. Каждый сбой возвращается как `ok: false` внутри `CallOutcome.value`. Это сделано намеренно: каждому ответвлению слоя инструментов нужно отрендерить структурный результат, а не заводить собственный try/catch.

### Почему первые два шага должны быть «каталог», а не «таблица рисков»

`riskOf()` возвращает `'dangerous'` для **неизвестного** метода (консервативное значение по умолчанию). Более ранняя версия использовала его для вывода «существует ли этот метод», что:

- ложно отклоняло 5 действительно существующих методов (`level.new`, `level.open`, `level.save`, `content.migrate`, `blueprint.import_t3d`)
- при этом пропускало любое выдуманное имя `editor.*`

Теперь вопрос — `isKnown()` (поиск по каталогу), а не `riskOf()`. **Существование — вопрос каталога, а не вопрос риска.**

## 3. Изоляция сессий и откат

### Проблема

UnrealAgentLink ведёт **один стек отмен агента на редактор**, общий для всех сессий DSH. Со стороны DSH несколько сессий могут управлять одним редактором одновременно.

Так что «отменить то, что сделала моя сессия» — операция, которую протокол не поддерживает.

### Подход

`src/sessions/state.ts` записывает каждый шаг, сделанный каждой сессией, и даёт каждому **глобально возрастающий номер** (`global`). Перед откатом он проверяет, образуют ли шаги этой сессии **чистый LIFO-суффикс** буфера этого редактора — то есть позднее ли последний шаг этой сессии, чем последний шаг любой другой сессии.

```
yes  → roll back, undoing only this session's steps
no   → undo nothing, and report both step lists
```

Лучше отказать, чем молча выбросить чужую работу.

### `rollbackOnDispose` по умолчанию false

Автооткат при уничтожении сессии звучит удобно, но **пользователь никогда об этом не просил**. По умолчанию выключено; включение — явное утверждение, что «окончание сессии должно отменить её работу».

## 4. Трансляция ошибок: почему она не читает текст

Текст ошибки переключается между китайским и английским вместе с локалью редактора (`result.message`). Его разбор привязал бы плагин к одному языку, да и текст может измениться в любой момент.

`src/errors/translate.ts` классифицирует только по **имени класса ошибки** (`NoEditorError`, `BridgeTimeoutError`, …) и **коду состояния**, на 16 видов, и для каждого даёт подсказку, что делать дальше.

Порядок: сначала имя класса, затем код состояния. Среди кодов состояния `410` отображается в `not-found`, `422` в `precondition`, а `504` в `timeout` — ни одно из этих отображений не очевидно, именно поэтому проверка 4 из `scripts/check-catalog.mjs` запрашивает исходный код C++, чтобы гарантировать полное покрытие.

**Почему отсутствие классификации вредно**: запасной вариант `engine-error` говорит «параметры в порядке, сломался сам редактор». Так что неклассифицированный код указывает модели ровно неверное направление. Самый ясный пример — `422`: он на самом деле означает «ввод был корректен, но ничего не записано», что не имеет ничего общего с «редактор сломан».

## 5. Автовыключатель и ограничитель частоты

### Автовыключатель защищает редактор

`src/resilience/breaker.ts`. Ключевое решение: **4xx записывается как `input` и не размыкает автовыключатель.**

Обоснование: агент, сделавший десять плохих вызовов подряд, — это **работающий** агент, а не убийца редактора. Только повторные **транспортные** сбои означают, что сам редактор в беде.

### Ограничитель частоты исправил настоящий баг

Ограничитель скользящего окна изначально пропускал **первого стоящего в очереди немедленно** — поэтому второй вызов в серии проходил мгновенно, и ограничение ничего не делало. Исправление — в `breaker.ts:schedule()`: первое освобождение выжидает оставшийся интервал вместо немедленного срабатывания.

## 6. Кольцо журнала

Редактор присылает `log.entry` (требует `ual.ForwardLogs 1` внутри редактора, что этот плагин не может включить удалённо).

`bridge.ts` держит кольцо ёмкостью 512: фильтруется по минимальному уровню (по умолчанию `Display`), упорядочивается по серьёзности, разбивается на страницы через `sinceSeq`, с нечувствительной к регистру фильтрацией по категории и тексту.

**Зачем делать это локально**: пересылать каждую строку журнала прямо в модель — значит утопить её контекст. Кольцо плюс фильтрация позволяют агенту доставать то, что нужно, вместо того чтобы получать всё навязанным.

---

## 7. Долгая работа: `ual_task`

В протоколе **нет семантики отмены**. `ual_task` оборачивает долгий вызов в настоящее задание DSH (вид `ual`), чтобы разговор мог продолжаться.

Две вещи должны быть вписаны в описание инструмента, иначе модель обязательно поймёт неправильно:

1. **Убийство задания останавливает только ожидание этого плагина.** Движок продолжает работать, и результат всё равно придёт.
2. **Пока выполняется блокирующая команда, редактор не отвечает ни на что** — даже на `sequence.render_status`. Поэтому не опрашивайте во время долгой задачи.

## 8. Поверхность инструментов: 12, а не 170

Если бы каждая из 170 команд была отдельным инструментом, 170 схем съедали бы промпт каждого запроса — а подавляющее большинство запросов не использует ни одной из них.

Поэтому:

- `ual_tools` перечисляет возможности (с фильтром по семейству или ключевому слову)
- `ual_schema` даёт точные имена ключей для одной команды
- `ual_call` выполняет

**Обнаружение возможностей занимает два шага, а не ноль.** Это осознанный компромисс: один лишний round trip в обмен на 170 меньше схем в каждом запросе.

## 9. Сгенерированные файлы и «таблицы, которые никто не импортирует»

Один класс дефектов повторяется в этом проекте и заслуживает отдельной заметки: **таблица, поддерживаемая вручную, создаётся, но никто её не импортирует.**

Случаи на данный момент:

| Таблица | Симптом |
|---|---|
| `REQUIRED_KEYS` | валидация обязательных ключей была мёртвым кодом, и `ual_schema` никогда не показывал `REQUIRED:` |
| `EXTRA_PARAM_KEYS` | у 4 методов `PARAMS_UNRESOLVED` были пустые списки параметров |
| `UAL_CODES` | `410`/`422`/`504` не классифицировались и откатывались к вводящему в заблуждение `engine-error` |

Общая нить: сама таблица была корректной, документированной и вычитанной — но во время выполнения читался другой путь.

Контрмера — заставить каждую проверку **спрашивать источник**, а не таблицу:

- проверка 3 в `check-catalog.mjs`: каждый ключ `requires` должен быть литералом, который встречается в исходном коде C++
- проверка 4 в `check-catalog.mjs`: `UAL_CODES` должен совпадать с множеством кодов, которые C++ действительно отправляет (включая общие шлюзы и формы выражений вроде `Code = bOk ? 200 : 207`)
- `gen-docs.mjs --check`: справочник команд должен совпадать с каталогом

Все это — **не самооправдывающиеся** проверки: сломайте источник или сломайте таблицу — и любая сторона провалится.

## 10. Две настоящие ловушки типобезопасности

### Свойства `undefined` всё ломают

dsh-tools запускает **двухстадийный** конвейер при выдаче результата инструмента:

1. `snapshotJsonValue(value)` — бросает `value is not lossless JSON`, если **любое** собственное свойство равно `undefined`
2. `validateJsonSchemaValue(schema, value)` — валидирует по схеме

Первая стадия строже схемы и **выполняется первой**, поэтому тест, проверяющий только схему, не может поймать этот класс багов.

Настоящий симптом: в **то самое мгновение**, когда редактор подключался и до того, как отправлял `project.info`, его запись `ual_status` содержала ключи вроде `project: undefined` — так что «инструмент, который вы читаете первым» падал в момент появления редактора.

Исправление — условное распространение вместо записи `undefined`:

```ts
...(session.info?.projectName !== undefined ? { project: session.info.projectName } : {})
```

### Выходная схема должна объявлять каждый ключ

Выходная схема инструмента использует `additionalProperties: false`, и реестр валидирует её **ключ за ключом**. Поэтому `attachment`, возвращаемый `ual_screenshot`, должен быть объявлен в схеме — иначе бросится `ToolOutputError` **в момент успеха снимка экрана**, при полностью рабочем текстовом пути.

В языке схем нет узла `ImageAttachmentRef`, поэтому его можно объявить только как `{ type: 'json' }`. Это расширяет выведенный тип до `JsonValue`, так что путь отображения должен сузить его обратно **проверкой во время выполнения**, а не утверждением `as`:

```ts
const attachment = imageRef(record.attachment)   // validates field by field
return attachment ? [{ type: 'image', attachment }, ...blocks] : blocks
```

Компилятор отказывается от простого `as` здесь (TS2352: типы недостаточно перекрываются) — это его требование проверки во время выполнения, а не вредность.

## 11. Стратегия верификации

```bash
npm run check
```

что эквивалентно:

```bash
tsc -p tsconfig.json --noEmit      # src
tsc -p tsconfig.test.json          # tests (src's tsconfig does not include tests)
vitest run                         # 173 tests
node scripts/check-catalog.mjs     # 4 reconciliation checks
node scripts/gen-docs.mjs --check  # справочник команд актуален на 9 языках
node scripts/normalize-doc-headers.mjs --check   # языковые панели каноничны в 54 файлах
node scripts/normalize-doc-links.mjs --check     # ссылки тела разрешаются из файла, в котором находятся
npm run install:dsh -- --profile web    # зарегистрировать этот плагин в профиле dsh
```

Тесты лежат в 9 файлах, разделённых по **роду дефектов, которые они способны найти**:

| Файл | Покрывает |
|---|---|
| `protocol.test.ts` | контракт `judge()`, правила сериализации |
| `translate.test.ts` | классификация и подсказки для всех 16 видов |
| `resilience.test.ts` | конечный автомат автовыключателя, очередность ограничителя частоты, `notifierFor` |
| `catalog.test.ts` | запросы к каталогу, защита цепочки прототипов, шлюз утверждения от начала до конца |
| `bridge.test.ts` | настоящий WebSocket: очереди, зависшие по таймауту, события, остановка |
| `tool-output.test.ts` | настоящее возвращаемое значение каждого инструмента через двухстадийный конвейер |
| `i18n.test.ts` | документация полна и внутренне согласована на всех 9 языках |
| `end-to-end.test.ts` | настоящая цепочка шлюзов + настоящий сокет + настоящие схемы инструментов |
| `installer.test.ts` | установщик профиля DSH: разбор аргументов, две записи манифеста, граница зеркала, отказ при блокировке |

**Почему `end-to-end.test.ts` должен существовать**: каждый другой тест заглушает один слой. Баг `REQUIRED_KEYS` — сгенерированный, документированный, вычитанный, никогда не импортированный — не был пойман ни одним юнит-тестом, потому что каждый слой был внутренне согласован в изоляции. Только соединив настоящую цепочку шлюзов с настоящим сокетом и подав это в настоящую схему, можно выявить **шов между слоями**.

По той же причине `tool-output.test.ts` использует **настоящие** `snapshotJsonValue` + `validateJsonSchemaValue`, а не пишет собственную проверку схемы — иначе дефект `ual_status` с `undefined` проскочил бы точно так же.

## 12. Конфигурация

Схема Schemastery в `src/config.ts` — **единственный источник значений по умолчанию**. `config` в `cordis.patch.yml` лишь переписывает умолчания, которые уже есть в схеме.

**Примечание о наслоении конфигурации DSH**: более поздний слой **заменяет** `config` этой строки целиком, а не глубоко сливает его. Чтобы переопределить любой ключ, вы должны переписать все ключи, которые хотите сохранить.

Переключателей вроде `allowDangerous` **сознательно не существует** — шлюз риска идёт через нативный шов утверждения `tools/pre-execute` в DSH, а не через собственный обход, изобретённый плагином.

## 13. Деградация при отсутствии необязательных зависимостей

`cordis.patch.yml` объявляет ровно одну жёсткую зависимость: реестр `tools` (через `inject`). Всё остальное читается через `ctx.get`:

| Сервис | Когда отсутствует |
|---|---|
| `jobs` | `ual_task` возвращает `kind:'background'` и объясняет, что недоступен |
| `fs` / `attachments` | снимки экрана деградируют до текстового пути с указанием причины |
| `agents` | подключение/отключение редактора не уведомляет агента |
| `approval` | `ask` превращается DSH в отказ |

Так композиция, опускающая один сервис, **теряет одну возможность**, а не отказывается загружаться.
