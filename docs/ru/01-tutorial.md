# Руководство: от нуля до работающего моста

Это сквозной путь. Цель: позволить агенту внутри DSH реально управлять вашим локальным Unreal Editor и понимать, что ему следует делать, а что повиснет.

Рекомендуемый порядок чтения: эта страница → [протокол](02-protocol.md) → [архитектура](03-architecture.md) → [справочник команд](command-reference.md).

---

## 1. Ментальная модель: сначала четыре факта

Прежде чем что-либо трогать, поймите: эти четыре факта определяют, как будет написана каждая последующая операция. Это не выборы архитектуры — это существующие ограничения UnrealAgentLink.

**① Направление обратное.** Этот плагин не звонит редактору; **редактор сам подключается**. C++-плагин UnrealAgentLink безусловно открывает `ws://127.0.0.1:17860` в `StartupModule`, а этот плагин слушает этот порт. Поэтому порядок запуска не важен: если редактор стартовал первым, он повторяет попытки каждые 5 секунд и всё равно подключится, когда плагин появится.

**② Аутентификации нет.** Ни токена, ни заголовка, ни подпротокола. **Сам порт и есть учётные данные** — кто может достать до 17860, тот может управлять редактором. Именно поэтому по умолчанию он слушает только loopback, и именно поэтому не следует менять его на `0.0.0.0`.

**③ Команды выполняются последовательно в игровом потоке.** Получив команду, редактор перепостит её в игровой поток, если он там уже не находится, а затем **выполняет её синхронно до завершения**. Два следствия:

- Команды к одному редактору выстраиваются в очередь естественным образом, и этот плагин тоже отправляет каждому редактору последовательно.
- **Пока выполняется блокирующая команда, редактор не отвечает ни на что** — даже на запрос прогресса вроде `sequence.render_status`. Всё остальное, что вы отправите, просто встаёт в очередь за ней.

**④ Отмены нет.** `query_task` / `cancel_task` в протоколе не существуют. Убийство задания `ual_task` останавливает только **ожидание этого плагина**; движок продолжает работать, и результат всё равно придёт. Это предложение вписано в описание инструмента `ual_task`, чтобы его прочитала модель.

## 2. Предварительные требования

| Пункт | Требование | Примечания |
|---|---|---|
| Unreal Engine | 5.0 – 5.8 | диапазон, объявленный в `.uplugin` плагина |
| UnrealAgentLink | сам C++-плагин | скопируйте в `Plugins/` проекта |
| Node.js | `^22.19.0 \|\| >=24.0.0` | см. `engines` в `package.json` |
| Среда выполнения DSH | любая рабочая установка | этот плагин загружается как bundle |

**Настольное приложение UEBox вам не нужно.** Это другой клиент того же производителя, который просто тоже использует порт 17860, поэтому одновременный запуск обоих — конфликт портов. См. [README § «UEBox не нужен»](../readme/README_ru.md#uebox-не-нужен).

### Установка UnrealAgentLink в проект UE

1. Скопируйте весь каталог `UnrealAgentLink` в `Plugins/` проекта (или в `Plugins/` движка для глобальной установки).
2. Перегенерируйте файлы проекта и откройте проект.
3. Убедитесь, что UnrealAgentLink включён в **Edit → Plugins**.

Плагин автоматически включает две свои зависимости из состава движка, `IKRig` и `PythonScriptPlugin` (см. `.uplugin`). Как только редактор стартует, он начинает подключение к 17860 безо всякой настройки.

> Если порт занят (например, настольным приложением UEBox), дайте редактору другой:
> `UnrealEditor.exe MyProject.uproject -UALServer=ws://127.0.0.1:17861`
> и измените настройку `port` на этой стороне соответственно.

## 3. Установка этого плагина

```bash
git clone <this-repo> dsh-unreal-agentlink
cd dsh-unreal-agentlink
npm install
npm run check      # typecheck + 154 tests + catalog reconciliation, one command
```

`npm run check` должен быть полностью зелёным, прежде чем идти дальше. Он проверяет три вещи: исходники типизируются и тесты типизируются, все поведенческие тесты проходят, и каталог из 170 команд сходится с реестром C++ запись за записью.

### Установка как bundle DSH

`package.json` объявляет `dsh.bundle.patch: ./cordis.patch.yml`, а этот файл делает ровно одну вещь:

```yaml
- insert:
    - id: unreal-agentlink
      name: dsh-unreal-agentlink
```

**Примечание**: в наслоении конфигурации DSH более поздний слой **заменяет** `config` этой строки целиком, а не глубоко сливает его. Чтобы переопределить любой ключ, вы должны переписать все ключи, которые хотите сохранить.

## 4. Первое подключение

### Шаг 1: убедитесь, что мост жив

Пусть агент вызовет `ual_status`. Следите за четырьмя полями:

```
listening: true
url: ws://127.0.0.1:17860
editors: [ { sessionId: "ue-xxxxxxxx", project: "MyProject", ... } ]
```

- `listening: false` → плагин не стартовал, либо порт занят. Ищите `EADDRINUSE` в журнале DSH.
- `listening: true`, но `editors: []` → мост ждёт. Убедитесь, что проект UE открыт и UnrealAgentLink включён.

В течение **первого мгновения** после подключения редактора его запись содержит только `sessionId` / `connectedAt` / `lastSeenAt` / `heartbeats` / `stale` — такие поля, как `project`, появляются только когда редактор отправит `project.info`. Это нормальное состояние, а не ошибка.

### Шаг 2: откройте для себя возможности

Не угадывайте имена команд. Два шага:

```
ual_tools  { filter: "material" }        → list the material family with a one-line summary each
ual_schema { method: "material.create" } → that command's param keys, required keys, result keys, status codes
```

Имена ключей в `ual_schema` **извлечены дословно** из обработчиков C++. Не пропускайте этот шаг: **UE молча игнорирует неизвестные или неверно типизированные ключи** — опечатка в имени ключа не вызовет ошибку, она просто «успешно» ничего не сделает.

### Шаг 3: первый настоящий вызов

```
ual_call { method: "level.get_current" }
```

Чистое чтение, без побочных эффектов. Он возвращает `result` редактора **дословно**; этот плагин не переформовывает его.

### Шаг 4: посмотрите на уровень

```
ual_screenshot { width: 1280, height: 720 }
```

Возвращается **настоящее изображение**, которое агент видит напрямую. Это лучше, чем `ual_call { method: "editor.screenshot" }`, который возвращает только путь к файлу.

Если `pending_shaders` / `pending_assets` в снимке экрана не равны нулю, вид ещё компилируется или подгружается, и это **не итоговый облик**. Не судите о материале как о сломанном по такому снимку.

## 5. Типовые рабочие процессы

### Изменение свойства актора

```
ual_schema { method: "actor.set_property" }        # check key names first
ual_call   { method: "actor.get_info", params: { targets: { names: ["Cube_1"] } } }
ual_call   { method: "actor.set_property", params: {
               targets: { names: ["Cube_1"] },
               properties: { Mobility: "Movable" } } }
```

Когда имя свойства написано с опечаткой, редактор **возвращает подсказки**, а не 404. Читайте подсказки; не повторяйте опечатку.

### Пакетные операции

Для известной последовательности работы используйте `ual_batch`, чтобы сделать это одним обменом:

```
ual_batch { calls: [
  { method: "actor.spawn", params: { asset_id: "cube", name: "A" } },
  { method: "actor.spawn", params: { asset_id: "cube", name: "B" } },
  { method: "actor.get_info", params: { targets: { names: ["A", "B"] } } }
] }
```

- Выполняется последовательно (редактор и так последователен) и **останавливается на первом сбое** по умолчанию; `continueOnError: true` это меняет.
- Ограничено `maxBatchCalls` (по умолчанию 12).
- **Если хотя бы один элемент опасен, весь пакет проходит через утверждение.** Запрос утверждения называет, какой именно это был элемент.

### Долгие задачи

Команды, блокирующие игровой поток, должны идти через `ual_task`:

```
ual_task { method: "sequence.render", params: { sequence_path: "/Game/Seq/Main" }, label: "Render main sequence" }
```

Он немедленно возвращает `jobId`, и разговор продолжается. Соберите результат через `job_output`.

Какие из них долгие: `sequence.render`, `cpp.compile`, `level.build`, `blueprint.compile_all`, `pcg.execute`, `pie.run`, импорт ассетов. Столбец таймаута в `ual_schema` помечает их «blocking».

**Не** опрашивайте редактор, пока выполняется долгая задача — он не ответит.

### Откат

```
ual_undo_history            # see what is in the buffer first
ual_undo { dryRun: true }   # rehearse
ual_undo                    # actually undo
```

UnrealAgentLink ведёт **один независимый стек отмен агента на редактор**, отдельный от истории Ctrl+Z пользователя. Этот плагин записывает, какой сессии DSH принадлежит каждый шаг, и **откатывает только когда шаги этой сессии образуют чистый LIFO-суффикс буфера**. Если за это время редактор затронула другая сессия, инструмент **не отменяет ничего** и сообщает оба списка шагов, вместо того чтобы молча выбросить чужую работу.

### Занятие блокировок ассетов

Перед многошаговым изменением ассета:

```
ual_locks { claim: ["/Game/Materials/M_Rock"] }
... make changes ...
ual_locks { release: ["/Game/Materials/M_Rock"] }
```

Редактор рисует в браузере контента значок «ИИ редактирует», и пользователь получает предупреждение, если начинает править его руками. Заявки от нескольких сессий этот плагин сливает в одну таблицу перед отправкой и отправляет повторно после переподключения редактора.

### Чтение журнала

```
ual_logs { level: "Warning", contains: "Niagara" }
```

Кольцо журнала по умолчанию пусто — пересылка журнала со стороны UE **выключена по умолчанию** и требует запуска `ual.ForwardLogs 1` внутри редактора (этот плагин не может включить её удалённо). `ual_logs` говорит об этом, когда возвращает пустоту.

При выключенной пересылке используйте вместо неё собственный журнал сообщений движка:

```
ual_call { method: "messagelog.list", params: { limit: 50 } }
```

## 6. Чтение сбоев

Этот плагин **никогда не парсит текст ошибки** (текст переключается между китайским и английским вместе с локалью редактора). Он классифицирует только по **имени класса ошибки и коду состояния**, на 16 видов.

| вид | Значение | Что делать |
|---|---|---|
| `no-editor` | ни один редактор не подключён | откройте проект UE; убедитесь, что плагин включён |
| `timeout` | истекло время ожидания, **команда, возможно, ещё выполняется** | **не отправляйте повторно**. Сначала уточните фактическое состояние командой чтения |
| `editor-lost` | редактор отключился | дождитесь его переподключения через 5 секунд |
| `queue-stalled` | предыдущая команда истекла по времени | проверьте `orphaned` в `ual_status` |
| `circuit-open` | повторные транспортные сбои разомкнули предохранитель | остановитесь, дождитесь охлаждения, проверьте `ual_status` |
| `rate-limited` | очередь ограничения частоты заполнена | притормозите |
| `not-found` | нет такого метода или ассета | найдите настоящее имя команды через `ual_tools` |
| `bad-params` | параметр отсутствует или неверно типизирован | проверьте имена ключей через `ual_schema` |
| `precondition` | предусловие не выполнено (412/413/422) | читайте `details`; 422 означает «ввод корректен, но ничего не записано» |
| `registry-busy` | реестр ассетов ещё сканирует | опрашивайте `content.registry_status` |
| `unsupported` | эта версия редактора не поддерживает | например, `anim.*` требует UE 5.5+ |
| `engine-error` | сам редактор сломался | читайте `result.message` (для людей) и `details` (для машин) |

**Таймаут — вид, который больше всех требует дисциплины.** В протоколе нет отмены, поэтому таймаут означает только «этот плагин перестал ждать» — команда с очень высокой вероятностью всё ещё выполняется в игровом потоке. Правильная реакция: проверьте `orphaned` в `ual_status`, затем уточните фактическое состояние командой только на чтение и **не отправляйте повторно**.

## 7. Конфигурация

Каждый ключ изменяем, и значения по умолчанию — «живой, но ленивый». Полная таблица — в [README § Конфигурация](../readme/README_ru.md#конфигурация). Несколько заслуживающих внимания:

- **`port`** — меняете здесь, и стороне UE тоже нужен `-UALServer=`.
- **`rateLimitRps: 0`** — отключает ограничение частоты.
- **`rollbackOnDispose: false`** — **не** отменяет автоматически при завершении сессии. Включение означает откат при уничтожении сессии, что обычно становится сюрпризом, о котором пользователь не просил.
- **`logForwardingEnabled: false`** — переводите в `true` только после запуска `ual.ForwardLogs 1` внутри редактора.

## 8. Устранение неполадок

**`ual_status` показывает `listening: true`, но редактора нет**
Проект UE не открыт, либо UnrealAgentLink не включён. Можно также посмотреть `LogUALNetwork` в журнале редактора: в норме вы должны увидеть `Connecting to ws://127.0.0.1:17860` и `Connected to`.

**`EADDRINUSE` при старте**
17860 занят. Чаще всего настольным приложением UEBox. Закройте его или переведите и редактор, и этот плагин на другой порт.

**Все команды возвращают `unknown-method` или отклоняются сразу**
Этот плагин пропускает только те 170 команд, которые действительно существуют в его каталоге. Подтвердите имя через `ual_tools`. Устаревшие команды (например, `editor.play`, `take_screenshot`) возвращают замену, которую следует использовать.

**Снимки экрана чёрные или недорисованные**
Проверьте `pending_shaders` / `pending_assets`. Ненулевое значение означает, что компиляция или подгрузка не завершилась. Поднимите `warmup_frames` и повторите.

**`ual_undo` отказывается работать**
Шаги этой сессии не образуют чистый LIFO-суффикс буфера — за это время редактор затронула другая сессия. Это **намеренная защита**, а не баг. Воспользуйтесь `ual_undo_history`, чтобы увидеть реальное содержимое.

**Изменение конфигурации не возымело действия**
Наслоение конфигурации DSH **заменяет** `config` этой строки целиком, а не глубоко сливает его. Вы должны выписать все ключи, которые хотите сохранить.

**`ual_task` убил задание, но редактор всё ещё занят**
Так и ожидалось. В протоколе нет отмены. Дождитесь завершения — или, что практичнее, не отправляйте другие команды, пока выполняется долгая задача.
